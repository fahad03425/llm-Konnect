# Module 6.3 (Part B) — Data Validation Documentation

This document describes the validation subsystem of **LLM-Konnect**.

Validation is deterministic, rule-based, vectorized (pandas), and 100% offline. It operates on the **canonical post-mapping table** generated by `apply_mapping()`.

---

## 1. Rule Codes, Severities & Descriptions

### Core Domain-Agnostic Rules (`canonical.py`)
Core rules enforce basic relational and transactional sanity. Core code contains **zero** domain vocabulary.

| Code | Severity | Description |
| :--- | :--- | :--- |
| `EMPTY_ROW` | `error` | All canonical data fields are missing or empty string. |
| `MISSING_REQUIRED_FIELD` | `error` | Required transaction fields (`date`, `amount`) or inventory fields (`product_id`/`description`) are missing. |
| `UNPARSEABLE_DATE` | `error` | Date field contains an unparseable timestamp string. |
| `DUPLICATE_ROW` | `warning` | Exact duplicate record detected across canonical data fields. |
| `INVALID_DATE_RANGE` | `warning` | Date is in the future (> today + 1 day) or older than 1990. |
| `NEGATIVE_QUANTITY` | `warning` | Quantity value is negative. |
| `LINE_TOTAL_MISMATCH` | `warning` | Calculated line total (`unit_price * quantity`) differs from reported `amount` by > 0.5 PKR/units. |

### Pharmacy Domain Pack Rules (`pharmacy.py`)
Pharmacy rules are registered via `PharmacyDomainPack` and evaluate pharmacy-specific compliance and stock risks.

| Code | Severity | Description |
| :--- | :--- | :--- |
| `MISSING_EXPIRY` | `warning` | Batch number provided without expiry date, or pharmacy stock item missing expiry date. |
| `INVALID_EXPIRY` | `warning` | Expiry date string could not be parsed into a valid timestamp. |
| `EXPIRED_STOCK` | `warning` | Stock item `expiry_date` is in the past (< today). |
| `MRP_OVERCHARGE` | `warning` | Sale `unit_price` exceeds printed Maximum Retail Price (`mrp`). |
| `BELOW_COST` | `warning` | `mrp` or sale `unit_price` is below cost/trade price (`cost`). |
| `MISSING_MRP` | `warning` / `info` | Maximum Retail Price (`mrp`) is missing for an item. |
| `UNREGISTERED_HINT` | `info` | DRAP registration number (`drap_reg_no`) is missing (flag for future enrichment). |

## 2. Public API Usage

```python
from app.schema.validate import validate, clean

# 1. Run Validation
report = validate(canonical_df, domain="pharmacy", table_kind="auto")

print("Verdict:", report.verdict)       # "usable", "usable_with_warnings", "not_usable"
print("Errors:", len(report.errors))
print("Warnings:", len(report.warnings))
print("JSON Report:\n", report.to_json())

# 2. Run Opt-In Cleaning Pass
cleaned_df, summary = clean(
    canonical_df, 
    options={"drop_empty": True, "trim_whitespace": True, "drop_duplicates": False}
)
print("Cleaned rows:", summary.cleaned_rows)
print("Changes made:", summary.details)
```

## 3. Extending Validation for New Domain Packs (e.g. Grocery)

To add validation rules for a new domain pack (e.g., `GroceryDomainPack`):

1. Define a subclass of `DomainPack` in `backend/app/schema/grocery.py`:
   ```python
   from app.schema.domain import DomainPack, Problem, registry
   import pandas as pd

   class GroceryDomainPack(DomainPack):
       @property
       def name(self) -> str:
           return "grocery"

       @property
       def extra_fields(self) -> list[str]:
           return ["is_perishable", "weight_kg", "origin_country"]

       @property
       def header_synonyms(self) -> dict:
           return {...}

       def validate_dataframe(self, df: pd.DataFrame) -> list[Problem]:
           problems = []
           # Add grocery-specific vectorized rules (e.g. weight_kg <= 0)
           if "weight_kg" in df.columns:
               bad_weight = df["weight_kg"] <= 0
               if bad_weight.any():
                   problems.append(
                       Problem("warning", "Weight must be positive", code="INVALID_WEIGHT", field="weight_kg")
                   )
           return problems

   registry.register(GroceryDomainPack())
   ```
2. Pass `domain="grocery"` to `validate(canonical_df, domain="grocery")`. The core validator will run core rules + `GroceryDomainPack` rules without modifying any core code.
